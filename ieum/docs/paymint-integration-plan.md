# 결제선생 연동 준비 메모

## 운영 방향

- 아이이음 본사가 결제선생 파트너로 계약한다.
- 각 도장은 결제선생 내부 구조상 파트너 소속 가맹 도장으로 관리하되, 아이이음 화면에서는 "도장 결제 계정"이라는 표현을 사용한다.
- 쌤포인트 충전금, 발송 건수, 사용량, 실패율은 본사 관리자에서만 확인한다.

## 비용 절감 정책

1. 완납자는 청구서 생성 대상에서 제외한다.
2. 같은 학생, 같은 월, 같은 payment_id 청구서는 중복 생성하지 않는다.
3. 이전 미납은 별도 청구서를 여러 번 보내지 않고 이번 달 청구서에 합산한다.
4. 재발송은 기본 24시간 쿨타임을 둔다.
5. 개발/검수 환경에서는 카카오 발송 대신 URL 생성 모드를 우선 사용한다.
6. 본사 잔액이 기준 이하이면 자동발송을 멈추고 본사 관리자에게 확인 대상으로 올린다.
7. 도장별 월 발송 상한을 설정할 수 있게 둔다. 0이면 제한 없음이다.
8. 콜백을 우선 사용하고, 상태 조회 API는 오래 남은 대기 건 점검용으로 제한한다.

## 결제선생 API 연결 전 확인할 질문

- hash 생성 방식: 문서에는 조합 문자열만 보이며 실제 암호화 알고리즘과 secret 사용 방식 확인이 필요하다.
- 운영 API base URL: 샌드박스는 문서 기준 `https://sandbox.paymint.co.kr/partner`로 확인했지만 운영 주소는 계약 자료로 재확인한다.
- 쌤포인트 차감 기준: `sendType=URL`과 `sendType=TALK`, 재발송, 파기 후 재생성의 과금 여부를 계약서에 명확히 적는다.
- 도장 결제 계정 등록 시 필수 사업자 정보 범위와 심사 실패 콜백 payload 샘플을 요청한다.
- 카카오 청구서 발신 주체와 학부모 표시명 정책을 확인한다.
- 콜백 재시도 정책과 결제 취소/부분취소 가능 범위를 확인한다.

## 구현 단계

1. 본사 결제선생 설정 화면과 DB 골격 구축
2. 도장 결제 계정 등록/콜백 저장
3. 청구서 생성/발송 로그 저장
4. 결제 완료 콜백으로 수련비 납부 상태 자동 반영
5. 본사 월별 사용량 대시보드
6. 도장 수련비 납부 화면에서 청구서 자동발송 연결
