# UI 문구 기준

이 문서는 원생관리와 이후 인페이지 정리 작업에서 사용할 화면 문구 기준입니다.

## 기본 원칙

- 사용자가 하는 행동을 기준으로 쓴다.
- 개발자나 시스템 내부 처리 단어를 화면에 그대로 노출하지 않는다.
- 버튼은 누르면 무엇이 되는지 바로 알 수 있게 쓴다.
- 상태값은 짧게 쓰되, 사용자가 다음 행동을 판단할 수 있어야 한다.

## 금지/대체 표현

| 피할 표현 | 화면 표현 |
| --- | --- |
| 큐, 대기열 | 문자 발송 준비, 문자 발송 기록 |
| paid | 납부 완료 |
| status | 상태, 현재 상태 |
| pending | 발송 준비, 확인 필요 |
| processing, 처리중 | 발송 중 |
| sent | 발송 완료 |
| failed | 발송 실패 |
| canceled | 발송 취소 |
| 생성했습니다 | 등록했습니다, 준비했습니다 |
| 게이트웨이 | 문자 발송폰, 문자 발송 앱 |
| 토큰 | 연결키 |

## 원생관리 화면 기준

- 목록의 `바로 처리`는 수정, 재원/휴관/퇴관 변경, 상담 메모, 문자 발송을 빠르게 끝내는 영역이다.
- `오늘 확인 처리`는 신호를 영구 삭제하는 기능이 아니라 오늘 화면에서 확인 완료로 숨기는 기능이다.
- 문자 관련 버튼은 `문자 발송`, `문자 발송 기록`, `발송 결과 확인`처럼 보호자에게 전달되는 결과를 기준으로 적는다.
- 생일 문자와 안부 문자는 사용자가 수정한 문구를 다음에도 쓸 수 있게 저장한다는 안내를 함께 보여준다.

## 문자 발송 화면 기준

- `문자 큐를 생성합니다` 대신 `문자를 발송 준비합니다`라고 쓴다.
- `문자 큐 확인` 대신 `문자 발송 기록` 또는 `발송현황 보기`라고 쓴다.
- `문자 게이트웨이` 대신 관장 화면에서는 `문자 발송폰`이라고 쓴다.
- `게이트웨이 토큰`처럼 연결용 기술 단어가 필요할 때는 `문자 발송 연결키`라고 쓴다.
